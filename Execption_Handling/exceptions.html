Exception Handling

What is Exception Handling?

In Java, error handling means dealing with abnormal situations that occur while a program is running, so the program can respond gracefully instead of terminating unexpectedly.

Error vs Exception

Java has a hierarchy called Throwable.

                 Throwable
                /         \
             Error       Exception
                         /        \
              RuntimeException   Other Exceptions

Error

Errors generally represent serious problems that applications normally should not try to recover from.

Examples:

OutOfMemoryError

StackOverflowError

Exception

Exceptions represent situations that an application can often handle or recover from.

Examples:

IOException

SQLException

ArithmeticException

NullPointerException

ArrayIndexOutOfBoundsException

So in an interview:

Error generally represents serious JVM-level problems, while Exception represents abnormal conditions that an application can potentially handle.

What Actually Happens Internally?

Consider:

public static void main(String[] args) {

    System.out.println("A");

    int result = 10 / 0;

    System.out.println("B");
}

Execution goes roughly like this:

main()
  ↓
println("A")
  ↓
10 / 0
  ↓
JVM detects division by zero
  ↓
creates ArithmeticException object
  ↓
searches for a matching handler
  ↓
no catch found in main()
  ↓
exception propagates
  ↓
JVM's default exception handler
  ↓
prints stack trace
  ↓
program terminates

The exception object contains

exception type
error message  -> e.getMessage()
stack trace   -> e.printStackTrace()

What If the Method Doesn't Handle the Execption?

This is where exception propagation comes in.

Suppose:


public static void divide() {
    int x = 10 / 0;
}

public static void main(String[] args) {
    divide();
}

divide() doesn't handle the exception.

So the exception moves upward:


divide()
   ↓
exception occurs
   ↓
divide() doesn't handle it
   ↓
return to main()
   ↓
does main() handle it?
   ↓
NO
   ↓
JVM

This is called exception propagation.

Stack Unwinding

Suppose:

main()
   ↓
methodA()
   ↓
methodB()
   ↓
methodC()
   ↓
exception

If methodC() doesn't handle it:

methodC()
   ↓
unwind
methodB()
   ↓
unwind
methodA()
   ↓
unwind
main()

Java searches backward through the call stack until it finds a matching handler.

This process is called Stack unwinding.

Checked vs Unchecked Exceptions

Checked Exception

Compiler forces you to deal with it.

Example:

FileReader file = new FileReader("data.txt");

FileReader can throw: FileNotFoundException

So Java requires you to either:

Handle it

try {
    FileReader file = new FileReader("data.txt");
}
catch (FileNotFoundException e) {
    System.out.println("File not found");
}

or declare it:

void readFile() throws FileNotFoundException {

    FileReader file = new FileReader("data.txt");

}

That's why it's called checked — the compiler checks it.

Unchecked Exceptions

Unchecked exceptions are subclasses of:

Runtime Exceptions

Examples:

NullPointerException
ArithmeticException
ArrayIndexOutOfBoundsException
IllegalArgumentException

Example:

int x = 10 / 0;

Java doesn't force:

try-catch

You can simply write:

int x = 10 / 0;

and compilation succeeds.

The problem happens at runtime.

14. throw vs throws

This confuses almost everyone initially 😄.

throw

Used to actually throw an exception.

throw new IllegalArgumentException("Age cannot be negative");

Example:

static void checkAge(int age) {

    if (age < 0) {
        throw new IllegalArgumentException(
            "Age cannot be negative"
        );
    }
}

You're saying:

"An invalid condition has occurred. I'm throwing an exception."

throws

Used in a method declaration to declare that a method may throw an exception.

static void readFile() throws IOException {

    FileReader file = new FileReader("data.txt");

}

You're saying:

This method might throw IOException. Whoever calls me should deal with it.

So remember:

throw  → actually throws an exception
throws → declares possible exceptions
